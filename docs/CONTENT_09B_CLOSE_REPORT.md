# CONTENT-09B-CLOSE — QA закрыт, активация ожидает решения

Проверка только чтением. Миграций, импорта, исправления live-данных и активации
не было; у записей 73 / 436 / 467 сохранены `execute=false`, `approved=false`.

## Точные расхождения

Полные строки извлечены **офлайн** только для двух таблиц из локального backup
CONTENT-07B. Его `fog_memories` точно совпадает с хешем baseline CONTENT-09B.
Для `scenes` восстановлены строки по сохранённым индивидуальным SHA-256 CONTENT-09A:
подбор затрагивал только `revision` / `updated_at` в минуте прежнего QA.
Каждая строка совпала с индивидуальным хешем; вся таблица — с хешем baseline
CONTENT-09B `41591fd93bfe606908329c34cc7ba600a8d031d20719eaeb27fcee1abcf142e1`.
Это проверенная реконструкция исходных значений, а не предположение об их содержимом.

| Сцена | `revision` baseline → после QA | Остальные изменения |
| --- | --- | --- |
| 5 | 13714 → 13722 | Только `updated_at` |
| 8 | 452 → 460 | Только `updated_at` |
| 9 | 382 → 390 | Только `updated_at` |
| 10 | 3144 → 3152 | Только `updated_at` |
| 11 | 284 → 292 | Только `updated_at` |

У всех пяти `updated_at`: **2026-11-13 10:43:31 → 11:11:19 UTC**.
Scene 6 и Scene 7 совпадают с baseline полностью. Геометрия, карты, свет и другие
содержательные поля всех семи сцен не изменены.

Причина: `CharacterActions::publish()` вызывает `SceneTransaction` для остальных
сцен кампании. Подтверждения Potion / Cure Wounds / Longsword дают соответственно
3 / 2 / 3 публикации, то есть ровно **+8**. В cleanup была восстановлена Scene 7,
а эти пять технических ревизий остались. Более ранние +6 относительно backup
CONTENT-07B уже присутствовали до CONTENT-09B и не входят в предлагаемый patch.

В `fog_memories` отличается единственная строка **id=21, scene_id=7,
scope=player:8**: только `bits`, **+13 498** ячеек, удалённых ячеек нет.
Остальные семь строк, размеры сетки и идентификаторы совпадают. Причина — временное
перемещение Лиры с (280, 260) в (1634.604, 483.509) скриптом QA и фиксация видимой
территории при snapshot через `FogExploration::record()`; возврат токена память
исследования не отменяет. Это не изменение HP, предметов или исполнения механик.

Текущие хеши обеих таблиц по-прежнему равны хешам сразу после CONTENT-09B.
Независимых сохранённых изменений относительно его baseline в этих таблицах
не найдено; более ранние изменения сохранены. Общие журналы MySQL отключены,
поэтому вывод основан на точном сравнении строк/хешей и цепочке вызовов, а не
на наличии журнала каждого SQL-запроса.

## Адресное исправление — только подготовлено

[План](CONTENT_09B_CLOSE_REPAIR_PLAN.json): пять UPDATE только `revision/updated_at`
по указанным ID и один UPDATE только `fog_memories.id=21.bits`. Других строк/полей,
пользовательских экземпляров и Compendium в patch нет.

Офлайн-симуляция возвращает обе таблицы к точным хешам baseline. Приватный patch
и `artifacts/content-09b-close/repair.php` подготовлены; default mode — READ ONLY.
Его preflight прошёл: проверяются хеши таблиц и полных строк, любые новые изменения
блокируют применение. Для будущего применения нужны отдельное разрешение по
точному SHA-256 плана и отключённые клиенты: возврат ревизий требует свежей загрузки
клиентов. Patch **не применён**; технические следы пока остаются в БД.
