# Docker для локального тестирования YTT

Эта инструкция объясняет и запуск, и устройство окружения. Команды выполняются
в **PowerShell** из `B:\DnD\YTT`. На другом компьютере замените путь на свой.
Нужен установленный Docker Desktop с Linux containers и WSL 2.
PHP, Composer, Node, MySQL и Redis на Windows для этого запуска не нужны.

## Быстрый запуск

Можно запускать проект двойным кликом по **`YTT-Start.bat`** в корне проекта.
Сначала откройте Docker Desktop и дождитесь **Engine running**. BAT-файл соберёт
и запустит контейнеры, дождётся готовности и откроет сайт в браузере.
Для остановки дважды щёлкните **`YTT-Stop.bat`** — кампании и загруженные файлы
сохранятся. Оба файла работают независимо от текущей папки терминала; можно
создать на них обычные ярлыки на рабочем столе. При ошибке окно останется открытым,
чтобы можно было прочитать сообщение.

Если хотите выполнить то же вручную:

1. Откройте Docker Desktop. Дождитесь **Engine running**.
2. Откройте PowerShell в папке проекта и выполните:

```powershell
cd B:\DnD\YTT
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\docker.ps1 up
```

3. После сообщения `YTT is ready` откройте <http://localhost:8090>.
4. Зарегистрируйте свой аккаунт и создайте кампанию. Предустановленного пароля нет.

Для текущего локального стенда 2026-10-29 выполнен перенос старой тестовой базы:
17 аккаунтов, 13 кампаний, 34 сцены и 414 ресурсов вместе с файлами. Старые тестовые
аккаунты уже доступны с прежними паролями; повторная регистрация для них не нужна.
Пункт о регистрации выше относится к новой установке с пустыми томами.
После переноса локальная база Windows и база Docker работают независимо.

Первый запуск скачивает базовые образы и зависимости, компилирует PHP-расширения
и собирает интерфейс, поэтому может занять несколько минут. Нужен интернет.
Повторный запуск использует кеш сборки и уже сохранённые данные.

`-ExecutionPolicy Bypass` относится только к этому процессу PowerShell;
команда не меняет постоянную политику выполнения скриптов в Windows.
Если запуск `.ps1` уже разрешён, можно писать короче: ` .\scripts\docker.ps1 up`.

## Обычные команды

В командах ниже `up` можно заменить на действие из таблицы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\docker.ps1 up
```

| Действие | Что произойдёт                                                           |
| -------- | ------------------------------------------------------------------------ |
| `up`     | Собрать актуальный код, создать/запустить сервисы и дождаться готовности |
| `down`   | Остановить и удалить контейнеры и сеть; сохранить тома с данными         |
| `stop`   | Остановить контейнеры, оставив их существовать                           |
| `status` | Показать состояния контейнеров, включая завершившийся `init`             |
| `logs`   | Смотреть последние сообщения и новые логи; Ctrl+C завершает просмотр     |
| `doctor` | Проверить зависимости приложения и heartbeat планировщика                |
| `test`   | Запустить PHP-тесты в отдельном контейнере и frontend-тесты              |

**Каждый следующий сеанс:** запустите Docker Desktop → выполните `up` → откройте
браузер. После тестирования выполните `down`, если хотите освободить ресурсы.
После изменения кода снова выполните `up` и обновите страницу.

## Базовые понятия

**Образ (image)** — подготовленный шаблон файловой системы и программ.
Например, `mysql:8.4` содержит MySQL, а наш `ytt-local:dev` — приложение,
PHP, Apache, PHP-библиотеки и собранный JavaScript. Образ сам по себе не работает.

**Контейнер (container)** — запущенный экземпляр образа с процессом внутри.
Из одного образа YTT работают сайт, Reverb, обработчик событий и планировщик,
но каждый выполняет свою команду. Контейнер можно пересоздать из образа.

**Dockerfile** — рецепт сборки нашего образа: откуда взять PHP, какие расширения
установить, какие файлы скопировать и какую команду запустить.

**Compose** — описание нескольких связанных сервисов в `compose.yaml`.
Он избавляет от необходимости вручную запускать каждый контейнер и соединять их.
У этого окружения имя `ytt-test`, поэтому его удобно найти в Docker Desktop.

**Том (volume)** — отдельное хранилище данных, живущее дольше контейнера.
Пересоздание контейнера не должно стирать подготовленные кампании.

**Порт** — номер сетевой точки входа. Запись `127.0.0.1:8090:80` означает:
«порт 8090 на этом компьютере направить на порт 80 внутри контейнера».
`127.0.0.1` ограничивает доступ вашим компьютером. Игроки из интернета к этой
локальной конфигурации не подключатся.

**Сеть Compose** позволяет контейнерам находить друг друга по имени сервиса.
Внутри `app` адрес MySQL — `mysql:3306`, Redis — `redis:6379`.
`localhost` внутри контейнера означает сам этот контейнер, а не Windows.

## Какие сервисы созданы и зачем

| Сервис      | Задача                                                                      | Доступ с Windows              |
| ----------- | --------------------------------------------------------------------------- | ----------------------------- |
| `app`       | Apache + PHP 8.4 обслуживают Laravel и собранный React/PixiJS               | <http://localhost:8090>       |
| `mysql`     | MySQL 8.4 хранит пользователей, кампании, сцены и задания событий           | Только внутренняя сеть Docker |
| `redis`     | Redis 7.4 хранит сессии и кеш                                               | Только внутренняя сеть Docker |
| `reverb`    | Доставляет обновления другим участникам через WebSocket                     | `ws://localhost:8085`         |
| `queue`     | Исполняет подготовленные события (Cue), включая отложенные шаги             | Порт не требуется             |
| `scheduler` | Раз в минуту запускает обслуживание, восстановление событий и heartbeat     | Порт не требуется             |
| `init`      | Готовит каталоги файлов и применяет миграции базы перед запуском приложения | Завершается с кодом 0         |
| `frontend`  | Дополнительный контейнер для тестов и проверок JavaScript/TypeScript        | Запускается по требованию     |

Несколько контейнеров здесь нужны для разных постоянно работающих процессов.
Одна команда Compose управляет ими как одним окружением. Если Reverb завершится
с ошибкой, Docker сможет перезапустить его отдельно от сайта.

Очередь Cue сохраняет задания в **той же MySQL**, что и состояние сцены.
Это требование существующего приложения: шаг и следующее задание фиксируются
в одной транзакции. Redis не заменяет эту очередь.

## Что происходит при `up`

1. `scripts/docker.ps1` находит папку проекта независимо от текущей папки терминала.
2. Если `.env.docker` отсутствует, скрипт копирует шаблон `.env.docker.example`
   и генерирует случайные APP_KEY, пароли MySQL и ключи Reverb.
   Существующий файл он сохраняет.
3. Скрипт проверяет доступность Linux-движка Docker.
4. Выполняется `docker compose --env-file .env.docker up --build --detach --wait`.
5. Docker собирает образ. Стадия `frontend` использует Node 22, `npm ci` и
   `npm run build`. Стадия `app` устанавливает PHP-расширения, Composer-зависимости,
   FFprobe для аудио и копирует готовый `public/build`. Node в серверном образе нет.
6. Compose запускает MySQL и Redis и проверяет их готовность через healthcheck.
7. `init` создаёт каталоги и выполняет `php artisan migrate --force`.
   Это обычное обновление схемы: `migrate:fresh` и автоматического удаления данных нет.
8. Стартуют Reverb, сайт, worker и scheduler. `--wait` ждёт проверок готовности.

`Exited (0)` у `init` — нормальный результат успешно выполненной подготовки.
Проверка `/up` подтверждает загрузку Laravel; она не заменяет проверку игры
в двух браузерах. `doctor` дополнительно проверяет MySQL, Redis, FFprobe,
каталоги, конфигурацию и планировщик. Heartbeat может появиться через минуту.

`--build` собирает образ; `--detach` запускает в фоне; `--wait` ждёт готовности.
Повторная сборка использует готовые слои: зависимости переустанавливаются, когда
меняются соответствующие lock-файлы или более ранние инструкции сборки.

## Как связаны файлы

| Файл                          | Назначение                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `Dockerfile`                  | Сборка Node-стадии и серверного PHP/Apache-образа                                              |
| `compose.yaml`                | Сервисы, команды, зависимости, порты, тома и проверки готовности                               |
| `.dockerignore`               | Исключает локальные секреты, Windows-зависимости, загруженные файлы и кеши из контекста сборки |
| `.env.docker.example`         | Шаблон параметров изолированного тестового окружения                                           |
| `.env.docker`                 | Сгенерированные реальные параметры; исключены из Git                                           |
| `deploy/docker/apache.conf`   | Ограничивает web root каталогом `public`                                                       |
| `deploy/docker/entrypoint.sh` | Подготавливает файловое хранилище и выполняет миграции для `init`                              |
| `deploy/php.ini`              | Существующие лимиты PHP: 64 MiB на файл, 68 MiB на POST                                        |
| `scripts/docker.ps1`          | Удобные команды и автоматическое создание конфигурации                                         |

В конфигурации Reverb добавлены отдельные публичные адреса для браузера.
Laravel публикует события на `reverb:8080`, а браузеру выдаёт `localhost:8085`.
Без этого браузер пытался бы найти имя `reverb`, известное только Docker.
В обычном запуске без `REVERB_PUBLIC_*` используются прежние `REVERB_*` значения.
Секрет Reverb в браузер не передаётся.

## Где хранятся данные

| Том                | Содержимое                                                           |
| ------------------ | -------------------------------------------------------------------- |
| `ytt-test_mysql`   | База с аккаунтами, кампаниями, сценами и заданиями                   |
| `ytt-test_storage` | Загруженные карты, токены, музыка, handout и служебные файлы Laravel |
| `ytt-test_redis`   | Данные Redis, включая кеш и сессии                                   |

На Windows эти тома находятся в Linux-хранилище Docker Desktop; это не папки
внутри репозитория. Их можно увидеть во вкладке **Volumes** Docker Desktop.
Обычный `down` сохраняет тома. `docker compose down --volumes` удаляет тома
окружения и их данные — это не команда обычной остановки.

Храните `.env.docker` вместе с резервными копиями базы и файлов: APP_KEY должен
оставаться прежним. Не удаляйте конфигурацию, чтобы «починить запуск», и не
меняйте пароли MySQL после создания тома без изменения пароля внутри MySQL.
Переменные MYSQL_* инициализируют пустую базу, а не меняют существующего пользователя.

Текущие `.env`, локальная база и `storage` репозитория в контейнеры не копируются.
Это новое тестовое окружение с отдельной регистрацией. Перенос существующих
кампаний требует согласованного переноса базы, приватных файлов и APP_KEY.

## Команды Docker без обёртки

После первого запуска скрипта `.env.docker` уже существует:

```powershell
docker compose --env-file .env.docker up --build -d --wait
docker compose --env-file .env.docker ps --all
docker compose --env-file .env.docker logs --tail 100 app reverb queue
docker compose --env-file .env.docker exec --user www-data app php artisan tabletop:doctor
docker compose --env-file .env.docker down
```

`exec` выполняет дополнительную команду внутри уже работающего контейнера.
`run --rm` создаёт отдельный временный контейнер и удаляет его после завершения.
Например, frontend-проверки:

```powershell
docker compose --env-file .env.docker run --build --rm --no-deps frontend npm run typecheck
docker compose --env-file .env.docker run --rm --no-deps frontend npm run lint
```

Для полного прогона используйте действие `test`: PHP запускается с временным
хранилищем, SQLite в памяти и явными тестовыми переменными окружения. Это важно:
переменные процесса из Docker имеют приоритет над обычными значениями phpunit.xml.
Не запускайте тесты с миграциями против рабочей тестовой MySQL вручную.

Исходники копируются в образ, поэтому изменение файлов на Windows не меняет
работающий сайт до `up --build`. Это воспроизводимый запуск для ручных тестов
с собранным интерфейсом. Vite HMR здесь не запускается.

## Частые проблемы

- **Engine stopped / cannot connect / dockerDesktopLinuxEngine not found.**
  Откройте Docker Desktop, дождитесь Engine running. Если он не стартует,
  посмотрите Troubleshoot и текст ошибки WSL. Сброс к заводским настройкам
  удаляет Docker-данные и не нужен для обычного запуска проекта.
- **Порт занят.** Измените в `.env.docker` `YTT_HTTP_PORT` и соответствующий
  `APP_URL`. Для WebSocket меняйте вместе `YTT_REVERB_PORT` и
  `REVERB_PUBLIC_PORT`. Например, HTTP 8091 и WebSocket 8086. Повторите `up`.
- **Сайт открыт, но нет связи.** Проверьте `status`, логи `reverb`, адреса
  `REVERB_PUBLIC_*` и порт 8085. Открывайте сайт через `localhost:8090`.
- **Ошибка сборки при скачивании.** Проверьте интернет/VPN и свободное место
  в Docker Desktop, затем повторите `up`; готовые слои сохраняются.
- **init завершился с ошибкой.** Посмотрите `docker compose --env-file .env.docker logs init`.
  Сначала устраните ошибку подключения или миграции, затем повторите `up`.
- **PHP/JS изменились, сайт прежний.** Повторите `up` и обновите страницу.
  `restart` перезапускает прежний образ и сам код не пересобирает.

Это локальный стенд с HTTP и привязкой к loopback. Для VPS нужны HTTPS/WSS,
настоящий домен, резервное копирование и отдельные настройки эксплуатации;
см. `docs/DEPLOYMENT.md`.

Для дальнейшего изучения: [модель Compose](https://docs.docker.com/compose/intro/compose-application-model/),
[ожидание готовности сервисов](https://docs.docker.com/compose/how-tos/startup-order/),
[тома Docker](https://docs.docker.com/engine/storage/volumes/).
