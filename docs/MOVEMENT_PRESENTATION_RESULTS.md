# Движение и обзор: реализация согласованного плана

11 ноября 2026. Локальный native runtime; изменения не опубликованы и не закоммичены.
Продолжение [аудита движка](MAP_ENGINE_PERFORMANCE.md) и
[согласованного плана](MOVEMENT_PRESENTATION_PLAN.md).

## Что исправлено

1. **WASD зависел от полного HTTP-цикла.** Один запрос за раз и шаг 35,9 units
   ограничивали устойчивую скорость величиной `35,9 / RTT`. Ограничение prediction
   71,8 units давало начальный отклик, затем остановку или замедление. Серверное
   время обработки входит в этот RTT. Высокий FPS сам по себе этого не исправлял.
2. **Normal drag одиночного героя применял полный путь мгновенно.** Добавлен отдельный `playback`:
   один атомарный commit с прежними коллизиями, бюджетом и triggers; анимация
   использует принятый сервером маршрут и duration. Teleport/override и Editor
   сохраняют прежнюю семантику.
3. **Повторная синхронизация отменяла Player playback.** Завершение route preview
   синхронно обновляет UI. Renderer ещё держал предыдущую сцену; изменившийся
   recipient-specific список props воспринимался как новая коллизия. Диагностический
   стек показал `setRoutePreview → renderer sync → finishMovements`. Renderer теперь
   фиксирует обработанную сцену до вызова обработчиков, способных обновлять store.
4. **Обзор обновлялся только на receipt и быстро завершал easing.** Тонкий индикатор
   радиуса следует presentation-позиции через uniforms; shader transition использует
   длительность принятого движения. Current mask не перемещается и не расширяется.
5. **Отмена не покрывала потерянный ответ после commit.** Esc прекращает неподтверждённый
   ввод, но неизвестный результат уже отправленной команды всё равно требует snapshot.
   Новый stream заблокирован до этого snapshot.
6. **Pusher сохранял `connected` секунду после закрытия сокета.** За retry delay
   продолжали уходить команды. Обрабатывается также `connecting_in`, ввод и
   presentation прекращаются сразу; после reconnect нужен новый явный ввод.
7. **Recovery терял полученный snapshot, если затем приходил обычный delta.**
   Контроллер проверял только последний `movementUpdate` при следующем включении.
   Теперь завершение recovery фиксируется подпиской в момент получения snapshot;
   обычное последующее обновление не блокирует WASD заново. Подписка снимается
   вместе с контроллером.

## Контракт и границы безопасности

Существующие endpoints, campaign/scene writer locks, idempotency, membership,
ownership, stream/sequence/origin и серверная проверка collision footprint сохранены.
Новых таблиц, зависимостей, transport или серверного игрового ticker нет.

`control/start` принимает capability `batching`. Приватный HTTP receipt содержит
`streamId`, `acceptedSequence`, `position`, `acceptedDistance`, `remainingCredit`,
`maxBatchDistance`. Он добавляется после публикации scene delta, поэтому не попадает
в Reverb payload других участников. Старый клиент сохраняет предел 36 units;
новый клиент без capability использует прежний режим.

Новый batch/credit ограничен 126 units (700 мс при 180 units/s). Credit начисляется
только по серверному времени, restart/retry его не создают. Сервер принимает
доступный по credit префикс, затем проверяет его прежними правилами. Коллизия
отклоняет префикс целиком без изменения sequence/credit/позиции. Клиент сохраняет
неподтверждённый остаток со всеми углами и разворотами, не переносит canonical state
в prediction и не отматывает видимый токен на каждом успешном receipt.

Один HTTP in-flight, интервал отправки ≥200 мс, timeout 900 мс. Prediction ограничена
251,8 units суммарного пути (один отправленный batch плюс один ожидающий), каждый
request содержит не более 16 промежуточных waypoints. При превышении границ
prediction останавливается; при отказе/неизвестном результате восстанавливается
авторитетная позиция. При реальной коррекции возможен заметный возврат — это
намеренно, чтобы не рисовать выдуманный маршрут сквозь скрытое препятствие.

**Prediction видимости нет.** Индикатор может только затемнить уже разрешённые
пиксели; `currentMask`, entity filtering, manual cover, explored memory и visibility
revision barrier остаются серверными. Плавная окружность не означает 60 новых LOS
расчётов/с. Новые области открываются только после разрешения сервера. Reset,
изменение геометрии и disconnect прекращают прежние presentation transitions.

## Методика измерений

- Реальная Scene 10 «Лесная таверна», 75 props, два существующих токена, исходные
  геометрия/освещение/видимость. GM + Player в отдельных Chrome contexts, 1680×1050,
  одинаковая camera, zoom 0,8. Состав и настройки возвращены после каждого прогона;
  scene revision и обычные серверные журналы закономерно изменились.
- Chrome 157, RTX 4070, Vite production build без `public/hot`. Baseline
  `app-Ciz_BW7C.js` уже включает предыдущую оптимизацию LOS; финальная сборка
  сравнительной серии — `app-bcZ-i2L0.js`. Окончательная `app-BSoqJij9.js` добавляет
  только защиту позднего отказа уже уничтоженного контроллера и повторного старта
  при его in-flight; на ней отдельно проверены геометрия, Echo, длительное движение
  и Editor/Runtime. Локальный PHP development server не равен production HTTP runtime.
- WASD D 1,4 с + ожидание завершения; drag 220 units + ожидание. По 10 повторов
  каждого при added RTT 0/100/175/250 мс. Задержка добавляется вокруг native fetch
  по половине до отправки/перед выдачей ответа приложению. Это воспроизводимая
  симуляция задержки приложения, не эмуляция потерь/пропускной способности TCP.
  Полный измеренный цикл включает server time; ResourceTiming отдельно не содержит
  искусственной задержки. Build/tests не выполнялись параллельно с замерами.
- Pixi ticker/позиции/uniforms, PerformanceObserver long tasks, GPU timer queries,
  CPU operation timers, Chrome DevTools CPU/trace. Trace-enabled диагностика не
  включена в сравнительную серию. Исходные JSON и screenshots сохранены в
  `artifacts/map-engine-performance/`, не в Git.
- В исходной baseline обработчик WASD останавливал всплытие `keydown`, поэтому
  точная baseline input latency не записана. Первое движение в исходной серии было
  уже на первом/следующем sample. Финальная серия записывает capture-event до
  игрового обработчика. Не следует выдавать эту смену измерителя за ускорение старта.

## Сравнение

WASD, по 10 повторов. Значения расстояния и паузы — p50 по прогонам; «пауза» означает
наибольший интервал между изменениями позиции во время удержания клавиши, включая
пограничный интервал у отпускания. Units — мировые координаты, не экранные пиксели.

| --------- | ------------------------------: | --------------------: | --------------------------: | ------------------------: | --------------------: |
| 0 мс      |                   203,2 → 253,5 |           101,5 → 9,4 |                   6,7 / 7,0 |                 8,6 → 8,6 |                 6 → 6 |
| +100 мс   |                   157,0 → 253,4 |           300,7 → 9,6 |                   6,4 / 7,3 |                 8,6 → 8,6 |                 5 → 5 |
| +175 мс   |                   122,7 → 253,4 |           433,9 → 9,2 |                   6,6 / 7,0 |                 8,6 → 8,6 |                 4 → 4 |
| +250 мс   |                   107,7 → 253,3 |           575,6 → 8,8 |                   6,6 / 7,0 |                 8,5 → 8,6 |                 3 → 3 |

Плюс один `/start` на управление в обоих вариантах. Это количество запросов за
полный сценарий с drain, не Hz. При +250 мс p50 полного step-цикла составил
457,7 → 456,5 мс: сервер не стал отвечать чаще, визуальное движение перестало
замедляться вслед за ним. Во всех 80 финальных сценариях позиции Player и GM
совпали в конце; ошибки canonical/presentation по последнему sample равны нулю.

**Выброс не исключён:** при +175 мс, WASD №8, последний step превысил timeout
уже после keyup. Произошла безопасная коррекция на 10,512 units, конечное расстояние
242,858 вместо ~253. Во время удержания скачка не было. Нельзя обещать отсутствие
коррекций при произвольно долгой серверной паузе.

Drag 220 units остаётся одной серверной операцией. Максимальный шаг позиции за
кадр: **220 → 3,54 units** по всей сравнительной серии. Анимация принятого пути
занимает около 611 мс и меняет позицию каждый render tick. Ожидание подтверждения
не устранено; local destination/path preview виден до него.

| Added RTT | Pointer-up → начало playback, до, p50 / p95 мс | После, p50 / p95 мс |
| --------- | ---------------------------------------------: | ------------------: |
| 0 мс      |                                      191 / 224 |           200 / 224 |
| +100 мс   |                                      305 / 314 |           307 / 482 |
| +175 мс   |                                      372 / 481 |          366 / 1982 |
| +250 мс   |                                      455 / 573 |           449 / 482 |

Выброс 1982 мс сохранён. `prediction-verified-175/drag-2`: приложение 1782,2 мс,
SQL 1651,9 мс; конкретно `insert ignore into scene_mutation_receipts` — 1625,9 мс.
`server-outlier.json` содержит обезличенный профиль без bindings. Причина ожидания
внутри MySQL пока не установлена; менять idempotency ради маскировки задержки нельзя.

При +250 мс частота кадров была и остаётся около **120 FPS**. Изменения позиции
при удержании: 68,5 → 119,9/с; новый clipped radius indicator — 119,9 uniform
updates/с. Изменения shader transition за тот же интервал: 10,7 → 36,9/с, включая
начальное ожидание первой маски. Во время активного transition uniforms меняются
на каждом кадре. Авторитетные маски: интервал 458 → 473 мс, то есть около 2,1–2,2 Гц.
Это разные показатели; последний не выдаётся за 120 LOS updates/с.

По всем сравнительным GM/Player samples: long tasks ≥50 мс **0 → 0**, наибольший
p95 кадра **8,7 → 8,6 мс**, максимальный отдельный кадр **14,6 → 18,5 мс**.
Максимум p95 по прогонам: Pixi render CPU 0,5 → 0,6 мс; GPU 3,26 → 3,51 мс;
vision tick после ≤0,1 мс (предел разрешения таймера). Новая анимация добавляет
небольшую работу, но не приближается к бюджету 16,7 мс на этом оборудовании.

Длинный маршрут: 12 удержаний по 1 с с разворотами, +250 мс. Пройденный путь
**924 → 2173 units**, максимальный интервал движения **567 → 11,7 мс**,
27 → 25 step HTTP; convergence после последнего keyup 808 → 581 мс.
Финальная разница GM/Player/canonical — 0. Это отдельный одиночный контроль
устойчивости, а не статистическая серия из десяти длинных прогонов.

Артефакты: `prediction-baseline-{0,100,175,250}`, `prediction-verified-{0,100,175,250}`,
`movement-comparison.json`, `prediction-long-final-250`, `movement-long-comparison.json`
в `artifacts/map-engine-performance/`. Скрипт `scripts/qa/movement-summary.cjs`
воспроизводит сводку из исходных покадровых JSON.

## Проверки корректности

- SQLite in-memory: DirectControl, TokenMovement, MovementTrigger, PlayerVision,
  RadialLineOfSight — 34 теста / 15 307 assertions. Проверены доступ, коллизии,
  частота/credit/sequence/expiry, приватность receipt, полная стоимость пути,
  однократные triggers и idempotent replay.
- Vitest: **111 тестов в 19 файлах**, все прошли: navigation/prediction, accepted
  path playback, vision, renderer/input, persistence/history и realtime;
  отдельные регрессии retry delay Pusher и уничтожения контроллера с in-flight.
- TypeScript + Vite production build, ESLint изменённых TS/QA и `git diff --check`
  прошли. Миграции и новые зависимости не требуются.
- Live GM + Player с added RTT 250 мс: Esc при in-flight, потеря ответа после commit,
  Esc + потеря ответа, timeout, серверный rejection, внешнее GM-перемещение, reconnect.
  Проверяются отсутствие повторной команды, convergence с snapshot сервера и
  работоспособность нового явного ввода после восстановления.
- Reorder/duplicate/revoke и delayed snapshot покрыты realtime tests. Live Echo:
  задержаны 15 реальных кадров Reverb на 700 мс дополнительно к HTTP +250 мс;
  WASD, drag, внешнее GM-перемещение и restart прошли, позиции сошлись. Использован
  документированный [WebSocketRoute](https://playwright.dev/docs/api/class-websocketroute).
- Live геометрия: W остановился перед стеной на y=754,011; D перед закрытой дверью
  на x=805,985; drag из двора в (600,600) прошёл принятым обходом через вход.
  Никакие двери и props для этих проверок не менялись.
- Editor: pan, zoom, prop drag preview; Runtime: pan, zoom, hover — около 120 FPS,
  p95 кадра 8,6–9,0 мс, без long tasks и browser exceptions. Snapshot сцены полностью
  совпал до/после, попыток scene writes не было. `movement-editor-verified` и
  `movement-runtime-final`; последний содержит Chrome zoom CPU/Performance trace.
- `prediction-profile-final`: отдельные DevTools CPU profiles и timeline traces
  WASD/drag на окончательной сборке. В sampled CPU profiles GC суммарно занял
  9,6 мс за 3,44 с WASD и 1,9 мс за 2,89 с drag; эти короткие прогоны не являются
  доказательством отсутствия любых долговременных утечек. Очередь prediction
  ограничена, новые uniforms переиспользуются, подписки освобождаются при destroy.

Сохранены также неудачные промежуточные прогоны. `prediction-faults-final` выявил
секундный retry delay Pusher; `prediction-reconnect-final` после исправления
подтвердил остановку на первом 20-мс sample (20,5 мс), один отправленный step,
convergence и явный restart. В `prediction-final-100` открытие stream превысило
900-мс timeout; затем найден описанный дефект recovery после обычного delta.
`prediction-recovery-verified` проверяет потерю ответа, snapshot, последующий
GM delta и успешное новое управление. Эти данные не подменяются успешной серией.
В соседнем `prediction-final-0/drag-9` Server-Timing показал 774,7 мс приложения,
из них 596,1 мс на commit/callbacks при 43,5 мс SQL. Это локализует длинный хвост
на сервере, но не доказывает конкретную дисковую/DB причину. При таком превышении
пределов безопасная остановка остаётся ожидаемой, а не маскируется большим timeout.

## Оставшиеся ограничения и развитие

Плавность собственного движения отделена от HTTP, но новые разрешения видимости и
начало отображения принятого drag остаются сетевыми. Промежуточная точная LOS-маска
вдоль маршрута требует отдельного согласования права на информацию и серверных
per-player разрешений; передавать скрытые blockers для клиентского LOS нельзя.

Серверные projection/LOS, SQL и очередь native HTTP всё ещё занимают заметное время.
Следующий профиль должен отделить эти затраты на реальном concurrent HTTP runtime.
Не повышать частоту запросов для компенсации задержек. Fog/LOS/lighting следует
развивать через независимые canonical permissions и presentation clocks.

Этот этап не меняет предел масштабирования token rendering. В предыдущем аудите
рост до 200 токенов увеличивал draw calls примерно до 1016; masks/graphics/text
нужно профилировать отдельно. Пространственный индекс и глобальный React-рефакторинг
не добавлены: на 75 props их стоимость не объясняла проблему. Этот результат не
является обещанием 60 FPS на любом оборудовании или при сотнях активных LOS observers.

Групповые GM-трансформации остаются в существующем контракте SelectionActions.
Новый playback относится к одиночному normal drag персонажа; редакторские props,
групповые edit-операции и teleport не получают искусственную задержку анимации.
