# Task 15 — Creation Hub & Token Identity

Локальная реализация, 29 октября 2026. Публикация на VPS не выполнялась.

## Работа мастера

- Кнопка **Добавить** над картой открывает Hub: Персонажи, Существа, Объекты,
  Заготовки, Столкновения, Заметка, Область. Hub доступен также из центра
  радиального меню и через правый клик по пустой карте.
- Персонажи и существа используют существующую коллекцию портретов токенов.
  Категория задаёт начальный пресет, не создаёт дополнительную копию материала.
  Клик по портрету открывает имя, пресет и HP; можно начать без портрета.
  Пресеты: Герой = player_character/friendly, Союзник = npc/friendly,
  Нейтральный = npc/neutral, Враг = npc/hostile.
- После выбора появляется режим размещения с привязанным к сетке preview.
  Клик размещает; Enter размещает в центре; Esc отменяет. Space + drag сохраняет
  обзор карты. Объекты остаются в режиме размещения для последовательных копий.
  Inspector не меняет ширину карты между повторными размещениями.
- Native drag из Hub использует существующие asset/template payloads. При
  перетаскивании портрета создаётся новый токен с пресетом категории; изображение
  уже существующего токена под курсором не заменяется.
- Подробные параметры остаются в Inspector; там можно отдельно поменять тип
  и отношение. Пресет не выдаёт права управления: игроку всё ещё нужно назначение
  владельца. Заметки и области остаются приватными; новая область выключена,
  пока мастер её не настроит.
- Новая сцена: визуальный выбор карты, загрузка PNG/JPEG/WebP или пустая сетка.
  Размер берётся из карты в пределах существующих ограничений. Выбранная карта
  и новая сцена сохраняются одной транзакцией; создание не включает сцену в эфир.

## Сохранение и совместимость

Расширены существующие TokenActions, SceneActions, TemplateActions и DTO. Новых
create/spawn endpoints, queues, правил боя или realtime протоколов нет.
Token identity передаётся тем же snapshot builder, включая отфильтрованные
события игрока. Копирование и сохранение заготовки сохраняют identity.

Аддитивная миграция `2026_10_29_000100_add_token_identity` добавляет kind и
disposition. Старые назначенные игрокам токены получают player_character/friendly;
остальные — npc/neutral. Враждебность не угадывается из имени или картинки.
Старые шаблоны без identity, включая прежние presentation kinds, по-прежнему
создаются как npc/neutral. Владение, HP, сцены и приватные файлы сохраняются.

Hub, форма и preview используют motion tokens и reduced-motion систему Task 14.
Движение preview обновляет только DOM transform, без React state на каждом кадре.
Подтверждение размещения появляется после успешной записи; ошибки очереди
сохраняют существующие Retry/Reload controls.

## Проверка

Доказательства находятся в игнорируемых `artifacts/task15-*`:
`task15-tests.log`, `task15-browser-report.json`, `task15-browser.cjs` и снимки
`hub`, `enemy-quick-create`, `placement`, `new-scene`, `hub-tablet`.

Автотесты: 94 PHP / 1214 assertions; 130 frontend / 27 файлов. Дополнительные
проверки: TypeScript, ESLint, Docker production build, Pint и git diff --check.
PHP-тесты выполняются через Docker helper с отдельной SQLite в памяти.

Browser QA выполняется в отдельной локальной кампании «Засада у маяка · QA15».
Используются копии существующих QA изображений; технический щит — fixture,
а не новый художественный портрет гоблина. Исходные кампании не редактируются.
Проверяются отдельные GM/Player contexts, создание hostile NPC, повторные props,
encounter/prefab, note/region, radial, reload, приватность, все три источника
новой сцены, native drag, отмена drop внутри Hub, CDP touch long press, планшетная ширина
и reduced motion. Поднятие пальца после удержания не запускает центральное
действие radial; следующий обычный tap работает.

Пределы: физический touch и Safari в этой задаче не проверяются. Создание и
удаление объектов сохраняют существующие границы Undo Task 12. При потере
ответа create требуется сверка с сервером, как и в прежнем пути создания.
