# Постоянный тестовый полигон

Обновлён 2026-10-30 по прямому запросу пользователя. Это подготовленные данные
локального стенда (MySQL `ytt_local`), а не автоматический seed для новых установок.

## Вход и состав

- Приложение: <http://localhost:8090>.
- Единственная кампания: **Постоянный полигон · Дом Флинна**, ID **5**.
- Единственная сцена: **Дом Флинна · полный игровой полигон**, ID **5**.
- ГМ: <http://localhost:8090/campaigns/5/scenes/5>.
- Игроки: <http://localhost:8090/campaigns/5/play>.
- Единственная игровая сессия: **Постоянная тестовая сессия**, ID **1**.

| Роль | Логин | User ID | Персонаж |
| --- | --- | --- | --- |
| ГМ | `gm@ytt.test` | 1 | Управляет всей сценой |
| Игрок 1 | `player1@ytt.test` | 2 | Керн · воин, Character ID 5 |
| Игрок 2 | `player2@ytt.test` | 8 | Лира · волшебница, Character ID 6 |

Актуальные пароли находятся только в локальном игнорируемом файле
`artifacts/permanent-playground-20261030/accounts.private.json` и выданы пользователю
в чате. Не переносить их в Git, документацию или память агента. Пароль каждого
аккаунта установлен при подготовке; не сбрасывать его ради очередного теста.

По прямому запросу Task 30 прежний полигон заменён настоящей картой Flinns
Townhouse (DnDavid). Два героя, четыре Compendium-derived NPC (два гоблина,
скелет, магмин), нейтральный Ивар, пять Props, три проверки, сундук, складской
ящик и corpse loot. Герои имеют оружие/броню/расходники, Лира — десять заклинаний
и ячейки I–IV. Бой подготовлен, но не начат. Подробный состав и QA:
[VERTICAL_SLICE_QA.md](VERTICAL_SLICE_QA.md).

Восстановление именно этого сценария после проверок:

```powershell
php artisan qa:townhouse
```

PHP использует текущие исходники; после изменения frontend выполнить `npm run build`. Команда
не запускается автоматически, доступна только в local/testing. Первый переход
требовал `--install`; последующие reset используют приватный manifest. Прежние
изображения, handout/Cue и завершённая история сохранены, но старые Cue не
являются инструкцией к новой игровой петле.

В текущем `.env` лимиты `REVERB_MAX_REQUEST_SIZE` и
`REVERB_APP_MAX_MESSAGE_SIZE` равны `262144`: стандартных 10 000 байт недостаточно
для текущих событий персонажей с подробными характеристиками. Сохранить эти
локальные значения при обновлении стенда; ключи доступа не менялись.

## Обязательное правило для дальнейшей работы

**Переиспользовать эти три аккаунта, кампанию, сцену и игровую сессию.**
Не создавать новые аккаунты, кампании, сцены или игровые сессии при каждом QA,
для другого размера экрана или новой задачи. Для одновременной проверки ролей
открывать отдельные browser contexts с уже существующими учётными записями.
Не запускать старые fixture/cleanup-скрипты как часть обычной проверки.

После проверок восстанавливать подготовленный набор командой `qa:townhouse`.
Она возвращает позиции, HP, ресурсы, добычу, экипировку и подготовленный бой.
Секретную заметку ГМ
игрокам не показывать. Новые сущности добавлять только в рамках требуемой функции;
для тестов на изолированных данных использовать `php artisan test` (SQLite в памяти).
Расширять или заменять постоянный набор только по прямому запросу пользователя.
