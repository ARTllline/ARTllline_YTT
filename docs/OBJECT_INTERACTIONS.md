# Взаимодействия с объектами

В Inspector токена или Prop откройте **Взаимодействия**, добавьте до восьми
действий и нажмите **Сохранить**. Для каждого действия задаются подпись, иконка
из фиксированного набора, результат и цель. Стрелки меняют порядок; флажок
временно выключает действие. Handout выбирается из текущей кампании, Cue —
из текущей сцены. Раздел доступен только GM.

Игрок открывает радиальное меню ПКМ, удержанием пальца 520 мс или клавишей
контекстного меню / Shift+F10 для выбранного объекта. Для движения пальца более
8 px удержание отменяется. После удержания отпускание пальца само не запускает
действие. Доступ к взаимодействию не требует владения токеном или возможности
перемещать объект: закреплённая дверь тоже может открывать материал.

В меню GM сохранены прежние инструменты. Кнопка **Действия** в центре переключает
круг на настроенные взаимодействия. Скрытые объекты взаимодействий не имеют.

## Результаты и безопасность

- **Открыть Handout** использует `HandoutActions::show` с единственным получателем —
  вызвавшим игроком. Действуют существующие личные каналы, проверка доступа к файлам,
  обнаруженные материалы и отзыв доступа. GM получает личный предварительный просмотр.
- **Запустить Cue** использует `CueRunner::start`: существующая очередь, ограничения
  параллельного запуска, epoch, проверка каждого шага и безопасные realtime-события.
  Cue может иметь общие эффекты, включая показ материала всем игрокам, как и прежде.
- Игрок посылает только `kind`, `id`, `actionId`, `epoch`, `clientMutationId`.
  ID цели и тип результата сервер читает из сохранённой конфигурации объекта.
- Snapshot и realtime DTO игрока содержат только `id`, `label`, `icon` доступных
  действий. Определения Cue, цель, выключенные действия и автор конфигурации не выдаются.
- Все записи конфигурации и исполнения блокируют кампанию и сцену в существующем
  порядке. Проверяются активная сцена, членство, видимость, принадлежность объекта,
  действие, цель и текущие GM-права автора конфигурации. Повтор идемпотентного запроса
  снова проверяет доступ; GM-preview нельзя повторно получить после смены роли.
- Удалённые цели и потеря автором GM-прав делают действие недоступным. Настройте
  действие заново от действующего GM. Изменение конфигурации требует явного сохранения;
  оно не входит в Undo/Redo расположения объектов.
- Старый общий путь `object.interact` сохранён для существующих триггеров. Именованное
  действие исполняет только выбранный результат и не запускает дополнительно этот триггер.

Миграция добавляет nullable JSON `interactions` в `tokens` и `scene_props`.
Старые объекты работают с пустым списком. Дублирование объекта сохраняет его действия;
при переносе в другую сцену недействительные ссылки Cue становятся недоступными.

## Проверка 2026-10-29

Локальное Docker-окружение пересобрано. Полный helper `scripts/docker.ps1 test`:
102 PHP-теста и 132 frontend-теста. Дополнительно проходят TypeScript и ESLint.
PHP-тесты выполнялись в отдельном SQLite in-memory контейнере, не в постоянной MySQL.

Две отдельные Chromium-сессии GM/Player подтвердили:

- Настройку двух действий Prop через настоящий Inspector, сохранение и доставку
  меню игроку по Reverb без перезагрузки.
- ПКМ → «Прочитать» → правильное «Письмо смотрителя» в существующем HandoutViewer.
- Видимый Token без владения → «Осмотреть» → Cue в существующей очереди →
  сообщение игроку по realtime.
- Удержание через Chromium touch events на viewport 390×844: меню помещается,
  отпускание пальца не посылает POST, последующий tap открывает Handout.

Автотесты покрывают скрытые/выключенные/удалённые действия, чужие объекты и кампании,
подмену цели, устаревший epoch, повторы запросов, безопасные snapshot/realtime DTO,
личную выдачу материала и потерю прав. Физический телефон и Safari здесь не проверялись.

Артефакты: `artifacts/object-interactions/` (ignored), включая логи, GM editor,
Player radial и touch screenshots. Для браузерной проверки создана отдельная локальная
QA-кампания «Объекты · Тайна смотрителя» (ID 15), аккаунты GM/Player 18/19,
сцена 50. Исходные подготовленные кампании не редактировались.

## Следующий этап: checks / DC

Добавляйте проверки в серверный путь взаимодействия перед вызовом результата.
Текущий игрок — субъект будущей проверки; GM-автор лишь разрешает подготовленный
результат. Бросок, DC, модификаторы и ветвление нельзя принимать как решение клиента.
Понадобятся фиксируемый результат проверки, политика повторных попыток и защита
от одновременных запросов; повтор `clientMutationId` не должен перебрасывать кости.
Секретные DC и ветки должны оставаться вне Player DTO.
